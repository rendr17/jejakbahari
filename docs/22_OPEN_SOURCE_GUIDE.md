# 22 — Open Source Guide

## 1. Tujuan

Membuat kontribusi kode dan data mudah, aman, dan dapat diverifikasi.

## 2. Jenis Kontribusi

- Bug fix.
- UI improvement.
- Test.
- Dokumentasi.
- Registry vessel.
- Port/geofence data.
- Route data.
- Provider adapter.

## 3. Data Contribution Principles

- Sertakan sumber.
- Jangan mengklaim data yang belum diverifikasi.
- Hormati lisensi dan terms.
- Jangan upload credential atau data privat.
- Gunakan confidence dan verification status.

## 4. Issue Templates yang Disarankan

- Bug report.
- Feature proposal.
- Vessel data correction.
- Port/geofence correction.
- Source/license concern.

## 5. Review

- Kode direview untuk correctness, security, test, dan scope.
- Data direview untuk evidence, provenance, dan confidence.
- Perubahan arsitektur memerlukan ADR.

## 6. Maintainer Responsibilities

- Menjaga roadmap dan scope.
- Meninjau source/license.
- Merespons vulnerability report.
- Menjaga dokumentasi.
- Menolak kontribusi yang berisiko atau tidak dapat diverifikasi.

## 7. Release

Gunakan semantic versioning:

- MAJOR: breaking change.
- MINOR: fitur kompatibel.
- PATCH: bug fix.

## 8. Community Safety

Proyek tidak boleh digunakan untuk stalking, doxxing, sabotase, atau klaim keselamatan. Data posisi kapal publik tetap harus diperlakukan bertanggung jawab.
